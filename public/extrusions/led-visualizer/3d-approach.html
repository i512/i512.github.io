How the 3D LED Preview Works

This project renders a 12×12×12 LED volume on a normal 2D canvas. It does not use WebGL. The renderer keeps LED positions in world coordinates, builds a camera coordinate system from yaw and pitch, orthographically projects 3D points into screen pixels, and inverse-projects pointer positions back onto the floor or a vertical height ruler for LED placement.

Rendering Pipeline

The preview is a small software renderer. Every redraw clears the canvas, projects geometric primitives, then draws lines and circles in the correct order.

1. World data

leds contains points like { x, y, z, r, g, b }. The cube bounds are fixed in box.

2. Camera basis

getCameraBasis() converts yaw and pitch into three unit vectors: right, up, and forward.

3. Projection

projectPoint() subtracts the cube center, measures the point along right/up/forward, and scales to pixels.

4. Canvas draw

drawFloorGrid(), drawBox(), drawLeds(), and drawPlacementMarkers() paint the final frame.

Coordinate System

The app uses a right-handed-ish world convention suitable for the LED box: x runs across the floor, y runs deeper across the floor, and z is height. The origin is the bottom-front-left corner. The camera points at target, which is the center of the box.

box = { width: 12, depth: 12, height: 12 } target = { x: 6, y: 6, z: 6 }

Vector Math Primitives

These small functions are the foundation. They keep the rest of the renderer readable and make the geometric intent explicit.

clamp(value, min, max) and snapToGrid(value, min, max)

clamp restricts a value to a closed interval. snapToGrid rounds first, then clamps. Placement uses this so pointer math cannot create LEDs outside the 12-unit box.

clamp(14.2, 0, 12) = 12 snapToGrid(4.6, 0, 12) = clamp(round(4.6), 0, 12) = 5

vector, add, subtract, scaleVector

vector is a lightweight constructor. The other three functions perform component-wise arithmetic. Projection starts by computing relative = subtract(point, target).

a = (2, 1, 0), b = (1, 3, 0) add(a, b) = (3, 4, 0) subtract(a, b) = (1, -2, 0) scaleVector(a, 2) = (4, 2, 0)

dot(a, b)

Dot product measures how much one vector points in another vector's direction. The renderer uses it to convert world-space offsets into camera-space coordinates.

dot(a, b) = ax * bx + ay * by + az * bz dot((3, 2, 0), (1, 0, 0)) = 3

cross(a, b)

Cross product returns a vector perpendicular to two inputs. The camera uses it to construct a clean orthogonal basis: right = cross(worldUp, forward).

cross(a, b) = ( ay*bz - az*by, az*bx - ax*bz, ax*by - ay*bx ) cross((0,0,1), (1,0,0)) = (0,1,0)

normalize(point)

Normalization keeps a vector's direction but changes its length to one. Basis vectors must be unit-length, otherwise projection scale would change as the camera rotates.

length = hypot(x, y, z) normalize((3, 4, 0)) = (3/5, 4/5, 0) = (0.6, 0.8, 0)

snapPointToGrid(point)

This combines per-axis snapping for placement. It preserves the world-coordinate model while forcing user-created LEDs onto integer grid coordinates.

snapPointToGrid({ x: 2.2, y: 7.8, z: 3.5 }) = { x: 2, y: 8, z: 4 }

Camera Construction

The camera is not a real object with a field of view. It is an orthographic view direction plus two screen axes. Right-dragging changes yaw horizontally and pitch vertically.

getCameraBasis()

First, spherical angles are converted to a unit direction. Then the direction is negated to get forward, because the view plane faces toward the target. Cross products derive the horizontal and vertical camera axes.

cameraDirection = normalize(( cos(pitch) * cos(yaw), cos(pitch) * sin(yaw), sin(pitch) )) forward = -cameraDirection right = normalize(cross((0,0,1), forward)) up = normalize(cross(forward, right))

getSceneMetrics()

This function converts canvas CSS size into projection constants. The scale is based on the smaller dimension so the cube fits regardless of panel shape.

scale = min(canvasWidth / 18, canvasHeight / 16) centerX = canvasWidth / 2 centerY = canvasHeight / 2

Projection: 3D Point to 2D Pixel

projectPoint(point)

This is the core of the visualizer. It subtracts the cube center, then uses dot products to ask: “How far is this point along the camera's right, up, and forward axes?”

relative = point - target screen.x = centerX + dot(relative, right) * scale screen.y = centerY - dot(relative, up) * scale depth = dot(relative, forward)

The y formula subtracts because canvas y grows downward, while camera up grows upward. The returned depth is later used for painter-style sorting and line fading.

resizeCanvas()

Canvas has CSS pixels and backing-store pixels. This function sizes the backing store by devicePixelRatio, then applies setTransform so all drawing code can continue using CSS pixels.

canvas.width = rect.width * devicePixelRatio canvas.height = rect.height * devicePixelRatio context.setTransform(ratio, 0, 0, ratio, 0, 0)

Picking: Mouse Pixel Back to 3D

Placement is the inverse of projection. The first click chooses x,y on the floor. The second click chooses z along a vertical line passing through that floor point.

screenToFloor(clientX, clientY)

This converts the pointer into a point on the camera plane, then walks along forward until it intersects the floor plane z = 0. The ray-plane intersection is solved with one scalar t.

worldPlanePoint = target + right * ((screenX - centerX) / scale) + up * (-(screenY - centerY) / scale) t = -worldPlanePoint.z / forward.z floorPoint = worldPlanePoint + forward * t

If forward.z is almost zero, the view is nearly parallel to the floor and the intersection would be unstable, so the function returns null.

heightFromScreen(clientX, clientY, floorPoint)

After x,y are locked, the app projects the bottom and top of the vertical column. It then projects the mouse onto that 2D segment with a dot product. The resulting fraction is clamped to 0..1 and mapped to 0..box.height.

segment = top - bottom amount = dot(mouse - bottom, segment) / dot(segment, segment) z = snapToGrid(clamp(amount, 0, 1) * box.height, 0, box.height)

handlePointerMove(event)

This function branches by interaction mode. Right-drag rotates the camera. With a selected floor point, movement updates height. Otherwise, movement updates the hovered floor point.

if rotating: yaw += dx * 0.01 pitch = clamp(pitch - dy * 0.01, -0.05, 1.25) else if selectedFloorPoint: selectedHeight = heightFromScreen(...) else: hoverFloorPoint = screenToFloor(...)

handlePointerDown(event)

Right click begins rotation. Left click either locks the current floor point or creates the final LED after height is selected.

right click → capture pointer and rotate left click + no floor selected → selectedFloorPoint = screenToFloor(...) left click + floor selected → addLed({ ...selectedFloorPoint, z })

Drawing Functions

boxCorners(), drawBox(), and drawFloorGrid()

boxCorners returns the eight cube vertices. drawBox projects them and connects the twelve edges. drawFloorGrid draws integer grid lines on z = 0.

corners = [ (0,0,0), (12,0,0), (12,12,0), (0,12,0), (0,0,12), (12,0,12), (12,12,12), (0,12,12) ]

Edge alpha is adjusted by projected depth, giving a cheap depth cue without lighting.

drawLine(a, b, color, width) and drawCircle(point, radius, fill, stroke)

These are thin wrappers around Canvas 2D primitives. Higher-level functions pass already projected screen points into them; they do not know anything about 3D.

drawLine(projectPoint(worldA), projectPoint(worldB), color) drawCircle(projectPoint(led), radius, fill, stroke)

drawLeds()

LEDs are projected and sorted by screen.depth before drawing. This simple painter's algorithm is sufficient because LEDs are circles, not intersecting 3D meshes.

projected = leds.map(led => ({ led, screen: projectPoint(led) })) projected.sort((a, b) => a.screen.depth - b.screen.depth) brightness = clamp((r + g + b) / (255 * 3), 0, 1) radius = 4.5 + brightness * 3.5 shadowBlur = 8 + brightness * 16

drawPlacementMarkers() and drawFloorPointGuides(point)

While hovering, the renderer draws guide lines on the floor to expose the snapped x,y. After the first click, it draws the vertical height line and selected z marker.

hover: draw floor crosshair + snapped floor point selected: draw vertical column from z=0 to z=12 + selected height point

render()

The frame function deliberately draws stable context first and transient UI last. That keeps placement markers visible above the box and LEDs.

clearRect(...) drawFloorGrid() drawBox() drawLeds() drawPlacementMarkers() update LED count and list

compileAnimation() and runAnimationIteration()

These functions are not part of the 3D math, but they feed the renderer. User code mutates LED colors over time; after each successful tick, colors are normalized and render() repaints the scene.

compiledAnimation(leds, time, iteration, delta, clamp, rgb, ...) normalizeLedColors() render()
The important architectural choice is that every operation stays in one of two spaces: world space for geometry and screen space for Canvas drawing. Functions such as projectPoint, screenToFloor, and heightFromScreen are the only bridges between those spaces.
